# 工作区初始化 —— 建骨架，不填内容

> 这个 skill 只铺格位。**格位里写什么由使用者决定**，尤其 `PROJECT.md` 与 `RULES.md` 的内容属于项目事实，不能由 AI 代填。
> 幂等是硬要求：任何已存在的文件一律跳过，绝不覆盖。

## 输入与依赖

**前置状态**：无。任何时刻可跑，重复跑的结果是「全部复用」。

**输入**：仓库根目录。`dev/` 已存在时先 `ls dev/`——脚本只报复用、不改动它们，但目录里可能已经躺着旧结构（见「不做的事」最后一条），那要人看过才能决定怎么并存。

## 流程

```bash
python3 <本 skill 目录>/scripts/init.py <仓库根目录>
```

脚本做四件事：建 `dev/research/` 与 `dev/features/`；从 `assets/*.template` 复制四份文档（目标已存在则跳过）；把工作流桥接块写进 `.workbuddy/memory/MEMORY.md`；打印「新建 / 复用 / 提示」清单。

桥接块的内容以 `scripts/init.py` 里的 `BRIDGE` 为准，本文不复述。它的作用是让不认识这套工作流的 agent 一进项目就知道该读哪份文档、该跑哪个入口——没有它，目录建好了也不会被用起来。

四份文档不齐时不写桥接块：索引指向一个不存在的文件，比没有索引更糟。脚本遇到模板缺失会跳过桥接、在「提示」里列出，并以非零码退出——先修模板再重跑。

## 四份文档各自的定位

四份文档各管一件事，最容易写歪的地方如下：

| 文档 | 只讲什么 | 最容易写歪的地方 |
|---|---|---|
| `README.md` | 这个工作区怎么用：格位表、产物在哪、状态在哪看 | 变成第二份 `PROJECT.md`，重复项目介绍 |
| `PROJECT.md` | 项目现在是什么样：整体目标、功能组织、怎么用 | 塞进 Feature 列表、分期号、进度——**这三样都不该进** |
| `RULES.md` | 可复用、跨分期的工程规则，含**目录承诺表**与**记忆层放什么** | 写成「注意事项」；承诺表写不出「不该出现什么」 |
| `ISSUES.md` | 不属于任何 Feature、但现在不做迟早要处理的事 | 变成待办清单（待办属于 plan 的任务清单） |

`PROJECT.md` 的更新触发判据只有一条：**这个变更能否被项目外的观察者感知。** 纯内部重构不更新它。

## 退出判据

五条同时成立：

1. `dev/` 下四份文档都存在；
2. `dev/research/` 与 `dev/features/` 都存在；
3. 没有覆盖任何既有的 `dev/` 文档（跑前跑后对比 `dev/` 下既有文件的内容，变了就是覆盖；记忆层的追加不算覆盖）；
4. `.workbuddy/memory/MEMORY.md` 里有工作流桥接块——首次运行新建或追加，再次运行报「已存在」；
5. 报告里列清了「新建」与「复用」。

`workspace-status` 随后应当能正常输出（此时会报「还没有任何 Feature」，这是正常的）。

## 不做的事

- **不填内容**。四份文档的内容与占位符由使用者填。AI 能帮着写，但那要走对话，不在这里顺手编。
- **不建 Feature 目录，不分配 F 编号**。编号由 `workspace-status` 在需要时给出，避免每个执行者各自取 max+1 撞号。
- **不写状态表**。状态只存在于 `spec.md` 与 plan 的文件头，任何索引表都是第二份状态。
- **不覆盖、不迁移**。工作区里已有别的文档目录（如 `docs/`）或旧版工作流结构（`dev/CONVENTIONS.md`、`plans/` 与 `checks/` 直接在 `dev/` 根下、没有记忆层）时，**原样保留、不强行迁移**，只在报告里说明两套并存，并指出以哪套为准（建议：新结构接手新需求，旧结构的遗留由人决定何时迁）。
- **只动自己那一段记忆**。桥接块用 `<!-- workspace-init:begin/end -->` 包住，只增删块内内容，块外一个字不碰；块已存在就跳过，不覆盖也不重写。
