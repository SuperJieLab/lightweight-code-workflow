## 一处 runtime 硬依赖

第 46 行「**必须派一个独立的只读子代理**」、第 76 行「Critical 修复后换一个新子代理重审」——子代理是本 skill 层二成立的唯一机制，而它不是所有 runtime 都有的能力。同一份文档在第 40 行对 `ocr` 的处理是「没装就跳过，不影响流程完整性——默认路径不能有外部依赖」，标准很明确：默认路径不许依赖外部东西。层二自己违反了这条。

后果具体：在没有子代理能力的 runtime 里，执行者只有两个选择——跳过层二（等于审查少一半，但报告上写着「两层都做了」），或者用同一上下文自审（正是本文要防的那件事）。两种都比写一份 fallback 差。

**处置：** 给层二加一条退化路径，写明「无子代理能力时」怎么办，并把退化后的可信度损失写进报告——让读报告的人知道这次层二是打折的。不给退化路径，等于默认所有 runtime 都支持子代理。
